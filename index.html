One place for every feed

Stop juggling tabs, apps and newsletters. Feedforge turns scattered sources into one tidy, predictable stream you control.

Feed or no feed

Native, discovered or guessed feeds, HTML pages or sitemaps – Feedforge always finds a way to your entries.

One clean JSON shape

Every source becomes the same normalized entries with stable SHA-256 IDs – build any reader on top.

Cached & resilient

Shared per-URL cache, stale copies when a source is down and lock-protected refreshes – polite to every site.

Safe by default

Only http/https, every redirect re-validated, private IPs blocked, hard size and time limits, no external XML entities.

Stateless & private

No account, no analytics. The server only caches sources – your reading state lives on your devices.

Plain PHP, no database server

A handful of PHP files and a file cache. No framework, no build step, no background workers – optional sync uses PHP's built-in SQLite.

How it works

Three steps from feed chaos to a calm reading flow.

  1. Send any URL

    A feed, a blog, a news page – call /api/?url=… with whatever you follow. It does not have to be an RSS link.

  2. Feedforge picks the variant

    Direct, discovered, guessed, HTML or sitemap – the most precise strategy wins, the result is cached per source.

  3. Use clean JSON

    Normalized entries with stable IDs, newest first – read them in Flint or build your own reader on top.

Meet Flint

Flint strikes the spark. Feedforge keeps the fire.

Flint is the reader that ships with Feedforge: an installable web app for your phone and your desktop browser. No endless timeline – every entry gets one decision, and your inbox stays calm.

Sync without an account

Create a vault on one device, scan its QR code with the other – done. No e-mail, no password. The server stores the key's hash and the latest state per entry, nothing else.

Only in your network

Sync answers to your local network by default. Away from home, Flint keeps working and queues every change – it catches up the moment you are back.

Local-first & offline

Feeds, states and entries live in your browser. The app starts instantly from cache, works on the train and never waits for a server to show your list.

Phone and desktop

Install Flint from the browser like an app. Swipe to triage on the phone, use j k o l x on the desktop, and share any page to Flint to follow it.

Leave Feedly behind

Import your OPML export and every source is resolved by Feedforge – including sites that never had a feed. Export works just as easily.

Private and light

No tracking, no third-party requests, no framework. A few kilobytes of plain JavaScript and one shared 24-hour cache per source keep it fast for you and polite to every site.

Self-host

Your server. Your feeds. Five minutes.

Feedforge is a handful of PHP files – no database server, no build step, no container required. If your server runs PHP, it runs Feedforge and Flint. MIT-licensed.

What you need

  • PHP 8.1+ with dom, libxml, mbstring – curl recommended
  • A web server – an nginx config is included, any server that routes /api/ to PHP works
  • A writable var/ – feed cache and sync vault, blocked from the web by the included config
  • Optional: pdo_sqlite – for Flint sync; answers to your local network only by default
shell
# get the code
$ git clone https://github.com/kreativ-anders/feedforge.git

# let PHP write cache + sync vault
$ sudo chown -R www-data: feedforge/var

# then open the reader in your browser
# https://feeds.example.com/app/

Frequently asked questions

What is Feedforge?

Feedforge is a self-hosted, centralized feed extractor. It turns any website or feed URL into normalized JSON entries with stable IDs – whether the site offers RSS/Atom or not.

What if a website has no RSS feed?

Feedforge does not need one. It probes common feed paths, extracts entries from the HTML (JSON-LD, article elements or links below the requested path) and finally falls back to the site's sitemap.

In which order are the variants tried?

From most to least precise: direct (the URL is a feed), discovered (declared in the HTML), guessed (common feed paths), HTML extraction and sitemap. The field source.strategy in the response tells you which one was used.

Which formats are supported?

RSS 2.0, RSS 1.0 (RDF) and Atom feeds, HTML pages and XML sitemaps. The output is always the same JSON shape.

How do I host Feedforge myself?

You need PHP 8.1+ with dom, libxml and mbstring (curl recommended, pdo_sqlite for Flint sync) and a web server with HTTPS. Clone the repository, make var/ writable for PHP and use the included nginx config. No database server, no build step.

What is Flint?

Flint is the reader that ships with Feedforge – an installable web app for phone and desktop. Every new entry lands in the inbox and gets one decision: read now, later or not interested. Read entries move to done.

Where does my reading state live?

On your devices. Flint keeps feeds and states locally and works offline. Feedforge itself only caches per source URL. If you turn on sync, Flint stores item states and your feed list in an account-free vault on your own Feedforge server – reachable from your local network only by default.

How does Flint sync without an account?

The first device creates a random vault key. Other devices join by scanning a QR code or opening the pairing link. The server stores only the key's hash and the latest state per entry – the most recent change wins. Offline changes are queued and sent as soon as the device is back in your network.

Can I move from Feedly?

Yes. Export your subscriptions from Feedly as OPML and import the file in Flint under Feeds. Flint exports OPML as well, so you can leave any time.

Where can I get Feedforge?

The source code is available on GitHub under the MIT license.
